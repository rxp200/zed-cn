# AI 代码讲解

在设置的 AI 分类中启用“代码讲解”，选择讲解渠道和模型。也可以通过右下角书本图标菜单（灰色关闭、绿色开启、高亮生成中）开关、选择模型、重新讲解、清除缓存和打开设置。开启意味着允许将当前阅读的代码和函数签名发送给明确选择的模型服务；不会回退到其他提供商。

讲解显示在相应代码上方并单独占行，不会遮住代码，采用淡绿色弱化显示，不写入文件，不进入 Git diff 或撤销历史，普通复制仍只复制代码。解释可能不准确，不能代替检查代码本身。

菜单仅列出已认证的可见渠道，并按渠道分组；认证成功不代表该账号拥有渠道目录中每个模型的调用权限，最终以服务端授权为准。设置入口打开 AI 分类下整组代码讲解设置，包含模型、函数行数上限、详细程度、输出语言及缓存。

## 加载和限制

只在聚焦的普通单文件代码编辑器加载，默认处理可见区域及其上方、下方各 100 行，停留 500 毫秒后请求。`preload_lines` 可以调整每一侧的预加载行数；`max_concurrent_requests` 调整每个项目的并发数，默认 5，不设最大限制，填入 0 时按 1 处理。较高的并发会同时保留更多请求、代码文本和流式响应，并增加内存、网络、模型服务压力及费用，请根据服务限额和机器资源设置。语法支持依赖文件语言的 Tree-sitter 解析器。无解析器、压缩文件、敏感文件和不可信项目不自动讲解。默认没有文件行数限制。

文件总行数不超过 `max_function_lines`（默认 500）且完整文本不超过单次 64 KiB 请求预算时，会把整个文件作为一个请求，让模型获得完整上下文。超过任一条件后才按函数或顶层语法单元拆分；其中单个函数超过该行数时，在函数上方询问是否继续。确认仅对当前内容有效，编辑后需要重新确认。大型函数按命名语法节点拆分，单个不可拆分且超出预算的节点不发送。项目预生成扫描采用相同策略。原有注释始终保留；默认跳过已有相邻注释覆盖的讲解位置。只说明函数目的及关键逻辑步骤，不为独立括号、结束符、空行添加解释，详细模式也遵守这一规则。

代码修改或配置变化会取消旧请求。编辑后保留旧讲解，书本菜单提示“代码已修改，当前讲解待更新”；手动保存或离开编辑器后重新生成，完整成功后再替换旧讲解。首次加载按完整单元逐个显示，当前可见单元优先于预加载，不再因小幅滚动取消整批请求。书本菜单显示批次进度和最近错误，可重试失败单元或停止当前讲解。失败结果不进入缓存。跨文件调用只依据已提供的代码解释，不自动上传仓库。

选中代码后可从右键菜单选择“深入讲解选中代码”，无需开启全局详细模式。立即打开的弹框展示原代码、排队提示和逐步生成的 Markdown 讲解，可停止生成或复制全文；完成后仍保留选区第一行末尾的回看图标。弹框复用 Markdown 预览的主题渲染，原代码按语法高亮代码块展示；标题栏固定，正文支持滚轮和右侧滚动条，代码块可复制或切换换行。

书本菜单的“扫描当前项目并预生成讲解”会先列出候选文件并确认，然后按配置并发把整个项目的讲解写入同一份本机缓存。再次执行扫描时，会先按当前文件内容、语言、模型和讲解配置计算全部单元的缓存键；缓存完整的未变化文件会整文件跳过，部分变化的文件只为新增或变化的单元请求模型。要强制重新讲解全部文件，请先从书本菜单清除全部讲解缓存。扫描不修改项目文件，没有项目总量硬上限；运行时可从书本菜单随时停止。停止会取消尚未发送的文件任务并阻止后续缓存写入，但已经发出的模型请求可能仍产生费用。

项目扫描只处理可见、受信任工作树里Git 仓库中已跟踪且未忽略的常见程序源码（明确排除未跟踪文件）。它拒绝 private 文件、项目外符号链接、超过 512 KiB 的文件、超长行、依赖和构建目录、生成/压缩代码，以及密钥、凭据、日志、数据库、状态和转储文件；JSON、YAML、TOML、Markdown 等配置或文档默认不批量发送。必须开启持久缓存并明确选择渠道和模型。

## 恢复与结果保留

自动讲解和项目扫描仅在服务明确返回 HTTP 429 或 503 拒绝时进行最多两次自动重试；每次重试前再次检查权限。遵循不超过 30 秒的 Retry-After，超过此时间交由用户稍后手动重试。认证错误、连接中断、响应中途失败和格式错误不会自动重发，避免不确定的重复计费。

深入讲解窗口提供“在编辑器中保留副本”，将点击时的原代码与讲解保存为本地只读临时标签页，方便搜索、复制及使用普通编辑器分屏对照；它不是持续更新的侧边面板，也不会自动写入项目文件。项目扫描失败时可在书本菜单复制最多 100 条失败详情，包含文件路径与错误原因。

## 排队与缓存身份

行内讲解不设置固定条目数量上限。模型根据代码的实际复杂度决定讲解数量，提示词要求覆盖重要逻辑阶段，同时避免机械逐行复述。客户端仍会校验 JSON、行号、重复位置、单条文字长度、控制字符、总响应字节和超时，这些是安全边界而不是讲解数量限制。

请求名额使用排队票据：深入讲解优先于自动讲解，自动讲解优先于项目扫描；等待超过五秒的任务提升优先级，同等级按进入顺序处理，避免后台扫描一直等待。已在执行的同内容请求不会阻塞其他内容的名额。取消任务会移除其排队票据。

缓存身份仅纳入所选提供者的配置（包括同名兼容提供者），修改其他渠道不再改变讲解缓存键。旧缓存版本不会复用。深入窗口和固定视图可使用“返回源码编辑器”切回原编辑器；这是编辑器焦点切换，不是逐条讲解的行号定位。

## 模型预算与继续阅读

自动讲解与项目扫描根据模型报告的上下文容量预留 4096 单位预算，并调用模型统一的 `estimate_tokens` 接口限制输入。模型实现可覆盖为与提供商匹配的 tokenizer；当前未覆盖的模型使用 Unicode 感知的保守估算，不能称为精确计数。过大的单元按完整文本行拆分，保留所属函数签名与行号映射；无法容纳的单行不发送，拆分片段也不保证单独构成完整语法。容量过小时会提示换用更大上下文模型。

深入讲解会在本地查询当前符号定义，最多收集五个非 private、受信任工作树定义附近的小段文本，并先在确认框展示路径、大小和完整内容；只有选择“加入并发送”才会发送，选择“仅发送选区”则完全排除候选上下文。它还可以“在右侧固定讲解”，共享正在生成的主题化 Markdown；“返回源码编辑器”会恢复原选区并滚动到可见位置。也可以转到 Agent 草稿继续提问，草稿不自动发送，其他关联文件仍由用户手动添加。

自动讲解在同一进程内复用最多 64 个同项目、同模型配置、同代码内容的成功结果；同时到达的同 key 请求排队，前一个完成后后一个复查共享结果和磁盘缓存，因此不会重复调用模型。清除全部缓存也清除此结果集。它不广播中间流，也不接管独立深入讲解请求。

## 缓存

数据库保存在应用本机数据目录的 `code-explanations/<项目标识>.sqlite`，不在项目 `.zed` 内。远程连接信息和项目根路径参与隔离；内容、语言、函数签名、模型配置、语言和详细程度参与缓存身份，键使用 SHA-256。

每项目默认讲解文本预算为 50 MiB，全局数据库预算为 500 MiB，自动淘汰较旧内容。数据库有少量结构开销；后台 SQLite 操作失败不影响编辑。关闭持久化不删除已有数据库，可使用状态栏清除缓存。缓存不保存完整源文件，但讲解本身可能包含敏感信息。

## 配置

```json
"code_explanations": {
  "enabled": false,
  "provider": null,
  "model": null,
  "target_language": "中文",
  "max_function_lines": 500,
  "max_concurrent_requests": 5,
  "preload_lines": 100,
  "detailed": false,
  "prefer_existing_comments": true,
  "cache_persist": true,
  "cache_max_bytes": 52428800
}
```

复杂语法、注释覆盖识别和 AI 返回行号都可能存在局限。Diff、多文件搜索结果、非聚焦编辑器和没有语法解析器的文件不在自动讲解范围内。

项目扫描会让等待中的交互讲解优先获得空闲请求名额；已经发送的请求不强行抢占。扫描在取得名额后重新检查权限并复查缓存，避免等待期间权限变化和重复请求。停止扫描会取消待处理任务；缓存清除代次和停止标记也在后台写入锁内检查。

项目扫描确认使用 Zed 内部主题弹窗，展示目标渠道/模型、扫描与排除规则、增量缓存行为、候选数量和大小。完整路径清单支持横向/纵向滚动，逐项显示大小，并可复制完整清单供核对。候选数不等于模型请求数：读取后仍会过滤不支持的内容，缓存完整的文件会整文件跳过，其余文件也会逐单元复用已有讲解。
