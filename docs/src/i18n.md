# 多语言（i18n）

本仓库使用统一的多语言目录管理**所有**用户可见文本。文案不在代码里散落硬编码，
而是从代码抽取到 `locales/` 下的语言文件，由 `crates/i18n` 在编译期内联为静态查找表。

## 目录结构

```text
locales/
  zh-Hans.json    简体中文（默认语言）
  en.json         英文
  meta.json       条目上下文（文件:行号、UI/噪声分类），供审校与工具使用
```

每个语言文件都是扁平的 `{"key": "文案"}` 映射。`key` 取规范化文本的 SHA-256 前 16 位
十六进制，保证同一段文本在全仓库共用一个条目；翻译时只需要改右侧的文本，不需要关心 key。

`meta.json` 由 `script/i18n_extract.py` 生成，记录每个条目出现在哪些文件的哪一行，
以及该处是否被判定为 UI 文本。

## 在代码中使用

```rust
use i18n::t;          // 或者直接用 i18n::t!(...)

// 无参数：返回 &'static str，可直接传给任何 GPUI API
Label::new(i18n::t!("2cd0f3be8738a86c"))
Tooltip::text(i18n::t!("436fafeb4605fecd"))

// 命名占位符：模板写作 {name}，返回 String
i18n::t!("d32c8c895631119e", count = files.len())

// 位置占位符：模板写作 {}，返回 String
i18n::t_args!("e1814aaaa1c70fa3", stats.kernel_version)
```

`t!` 的返回值类型与原来的字符串字面量一致（`&'static str`），因此可以直接替换既有调用点，
不改变任何函数签名。缺 key 时回退英文，再回退 key 本身。

## 切换语言

在设置界面的「通用 → 语言 → 界面语言」下拉框中选择，或直接编辑 `settings.json`：

```json
{
  "language": "en"
}
```

- 可选值为 `locales/` 下已编译的语言 ID（`zh-Hans`、`en`），下拉框会自动列出；
- 未设置或不可识别时使用默认语言 `zh-Hans`；
- 修改后立即生效，不需要重启。

## 新增一种语言

1. 复制 `locales/en.json` 为 `locales/<locale-id>.json`（例如 `locales/ja.json`）；
2. 翻译其中的文本值，保持 `{name}` 与 `{}` 占位符原样；
3. 重新编译。新语言会自动出现在可用语言里，无需改代码。

## 工具链

| 脚本 | 用途 |
| --- | --- |
| `script/i18n_extract.py` | 扫描 `crates/` 与 git 历史，重新生成 `locales/`。`--from-ref HEAD` 可从指定提交抽取 |
| `script/i18n_codemod.py` | 把代码里的字符串字面量改写为 `i18n::t!(key)`。`--all` 全仓库，`--multiline` 处理跨行 `format!`，`--dry-run` 预览 |
| `script/i18n_translate.py` | 翻译工作台：`export` 导出待翻译条目，`import --by-text` 按原文写回译文 |
| `script/i18n_check.py` | CI 门禁：校验 key 存在、中英文占位符一致、统计覆盖率与孤儿条目 |

典型工作流：

```bash
# 1. 代码里新写了一段中文 UI 文本，先迁移它
script/i18n_codemod.py crates/some_crate/src/some_file.rs

# 2. 抽取/更新目录（含从上游合并后恢复的英文）
script/i18n_extract.py

# 3. 校验（CI 会执行同样检查）
script/i18n_check.py

# 4. 补齐缺失的翻译
script/i18n_translate.py export --lang en --limit 100 --out /tmp/batch.json
#   编辑 /tmp/batch.json 后：
script/i18n_translate.py import --lang en --source /tmp/batch.json --by-text
```

## 判定规则

只有用户可见文本需要翻译：按钮、菜单、标签、tooltip、placeholder、toast、弹窗、
设置项、错误提示等。以下内容**不**翻译，工具会自动跳过：

- 日志、`telemetry::event!`、panic 与断言信息；
- 测试代码、夹具数据、`#[cfg(test)]` 区域；
- 协议标识、URL、模型/工具载荷、内部诊断；
- `#[strum(serialize = ...)]`、`#[error(...)]` 等属性与 `const` 初始化中的字符串；
- `mod.rs` 同级的构建脚本与 `crates/i18n` 自身。

跨行 `format!` 与多行字符串由 `--multiline` 模式或人工迁移处理；带格式说明符的占位符
（如 `{value:?}`）需要人工改成显式实参。
